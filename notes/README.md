# notes/

This folder holds **write-ups, learnings, and design decisions** — the "why" behind the code, not the code itself.

## What goes here

- Conceptual write-ups (e.g. explaining the observe–think–act loop in your own words)
- Design decisions and the reasoning behind them (why this folder structure, why this tool pattern, etc.)
- Learning log / progress notes as you move through the phases
- A living `roadmap.md` tracking the overall plan and what's done vs. upcoming

## Suggested layout

```
notes/
├── roadmap.md               # overall plan + phase tracking
├── observe-think-act.md     # conceptual write-up
└── learning-log.md          # running notes on progress, gotchas, decisions
```

## Guidelines

- Write these for future-you — assume you'll forget the context in 3 months
- Keep entries dated where relevant, so the log reads chronologically
